# Changelog

## 0.2.4 (2026-11-27)


### Changes

* ctrader-mcp-servers: for a Local weekly or monthly bar the agent sends a `from` at or before the bar's `timestamp`, as for a daily bar, since a `from` later than the `timestamp` leaves the bar out: a `from` at 00:00Z of a Monday leaves out the weekly bar stamped on the Sunday evening, and a `from` at 00:00Z of the first day of a month leaves out the monthly bar stamped on the evening before.
* ctrader-mcp-servers: the agent applies the rule on `swap` and `netProfit` of a Local `get_order_history` item to a `get_deals` item too, so before it reports the result of a deal with a non-zero `swap` it compares the deal's fields.
* ctrader-cli: a weekly or a monthly bar of `candles` is in a date-only window only when its stamp lies on or after `--from`, so the agent passes the Sunday before a week that starts on a Monday as `--from`, and for a month the last day of the month before, as `--from=2026-09-30` for the October bar.
* ctrader-cli: on a `deals` deal whose `swap` is 0 the agent reads `netProfit` as `grossProfit` plus `commission`, and on a deal with a non-zero `swap` it compares the fields before it reports a result: when `netProfit` equals `grossProfit` plus `commission` plus `swap`, it already contains the swap, and when it equals `grossProfit` plus `commission`, the agent adds the deal's `swap` to it.
* ctrader-mcp-servers: the last bar of a Remote `get_trendbars` answer can be the bar of the period still in progress, whose `close` and `volume` can differ from one read to the next, so the agent gives the last bar with the period it holds and presents it as finished only once its period has ended by the current time or, without one, by the newest quote read with it; it answers a question that names an hour, day, week or month from the bar that holds that period, never from a bar picked by its place in the answer, and a last bar not shown finished still answers a question about the period it holds or about the latest bar: the agent reads the symbol's quote, gives the bar as the bar at the time of the read and says that it can still change or, for a closed market, that the market has had no quote since its last quote, and where the session gives no time of day that the current time would show whether the bar is finished; for a period's close or another value that must come from a finished bar it gives the bar before the last one as well, names both by their periods and says which is finished; in a figure over several bars it either includes a last bar not shown finished and says so or leaves it out and reads one bar more, naming the bar the figure ends with; the Remote and the Local pre-trade snapshot say whether their recent bars can end with the bar still in progress.
* ctrader-mcp-servers: a Remote `get_deals` deal is an execution, the openings of positions among them: a closing deal reads `closing` true and carries `closePositionDetail`, an opening deal reads `closing` false, and a deal's `tradeSide` is the side of its execution, so the agent reads the deal that closes a long position as `SELL`, counts closed trades from the closing deals, and calls the sum of a position's closing deals its round trip only when the deals read hold its opening deal and the `closedVolume` of its closing deals adds up to the opening deal's `filledVolume`, else reads further back or presents the sum as the result of the closes so far or inside the range; a sum over part of a round trip's closing steps, on either server, is presented as the result of those closes.
* ctrader-mcp-servers: a stop-limit order whose limit is its stop price, as every Local `place_stop_limit_order` places it and a Remote STOP_LIMIT order with `slippageInPoints` 0, fills at its stop price or ends canceled without a fill once the market reaches the stop price, so the agent tells the user so before the confirmation and, since an order gone from the pending orders is not thereby filled, looks for the position the order opened before it reports a fill or an end without one, on Local by a `label` of the order's own in the open positions and in the history, which also holds a position that has closed since, while for an order without a `label` of its own it reports no fill, says that the Local reads do not show whether the order filled, and names the open positions without a label of the order's symbol and side that it can have opened.
* ctrader-mcp-servers: the agent judges a Local stop loss or take profit by its price key, `stopLossPrice` or `takeProfitPrice`, never by its pips key, which can read `null` on a pending order whose leg is set, and reports such a leg by its price; after a change of protections on either server it compares each level read back with the level the user confirmed, for a Local level sent as a pip distance the price that distance gives from the order's `targetPrice`, and when a level reads back at another value it tells the user what reads back and sends nothing further without the user.
* ctrader-mcp-servers: after a Local partial close the `commission` of the position is that of the volume still open and each closed part is a `get_order_history` item of the same `positionId`, so for what a position has cost or earned so far the agent totals the `netProfit` of the closed parts as the result of the closes so far, with their `commission` and `swap` beside it, gives the figures of the open part apart, and totals no figure across the two, since a `get_positions` item whose `swap` is 0 reads `netProfit` as `grossProfit` plus twice its `commission`.
* ctrader-mcp-servers: a Remote deal's `filledVolume` and the `closedVolume` of its `closePositionDetail` are in the unit of `volume`, so the agent divides them by 100 for units of the base asset before it reports a size.
* ctrader-mcp-servers: the agent gives the Remote used margin as `equity` minus `freeMargin` of one `get_balance` answer and says that it is derived, and says that the Remote server serves no margin level, which rests on the estimated closing commission, instead of computing one.
* ctrader-cli: the deals of `deals` are those that closed all or part of a position, each closing step its own deal, and `side` is the side of the position, so the agent reads the `Buy` of the deal that closes a long position as the side of that position, groups the deals of a position by `positionId`, reads `position` with that id to learn whether part of it is still open, gives the figures of that open part apart and presents the total of the deals as the result of the closes so far, and reads the opening order from `orders-history`; an entry of `positions` carries that id as `id`.
* ctrader-cli: the agent does not present `high`, `low` and `open` of `price` and `prices` as a day's range or open, since the answer names no period, and takes a range from `candles`; since a quote comes back also while the market is closed, it reads `sessions` before presenting `spread` as a cost and, when the time of the read in the header line falls outside the sessions, says that the market is closed and does not present the spread as a current trading cost.
* ctrader-cli: since a `deals` or `orders-history` command that is the first history request of a session can answer with an empty list and exit 0, the agent reads both commands in one shell session instead of on a launch line: it sends the same command three times on standard input, 5 seconds apart, with its arguments by position as `ctrader-cli --commands` lists them, and uses the last result once it agrees with the one before; `scripts/extract_result.py` takes `--last` with `--key` to print the last value that holds the key.
* ctrader-cli: `spread` of `price` and `prices` is in pips, the distance from `bid` to `ask` divided by the symbol's `pipSize`, so the agent takes the same distance as a price as `spread` times `pipSize`; since an open market can quote `bid` equal to `ask` and `spread` 0.0 too, the agent does not take a spread of 0.0 as the sign of a closed market, decides it from `sessions`, and in an open market presents the spread, 0.0 included, as the spread at the moment of the read.
* ctrader-cli: the newest bar of the count form of `candles` is the last closed period, so when the user asks for the current day, hour or another period still in progress the agent says that `candles` returns closed bars only, names the newest bar by its `timestamp`, and builds the period in progress so far from the closed bars of a shorter period, saying which bars it rests on.
* ctrader-cli: an order placed through the CLI has no expiry, no choice of the stop trigger method, no market range on a market order, no label or comment, and one stop loss and one take profit with no trailing stop loss, no break-even protection and no further take-profit levels, so when the user's request includes one of these the agent says before any command that the CLI cannot set it, runs nothing until the user agrees to the order without it or chooses to place it in cTrader, and names it in the confirmation of the placement.
* ctrader-cli: `--limit-range` of `order place-stop-limit` sets the order's limit that many pips beyond its stop price, a range of `0` putting the limit at the stop price, and such an order fills at the stop price or is cancelled without a fill; the agent tells the user so before the placement and, once the market has reached the stop price, reads `orders`, `positions` and the order's `status` in `orders-history` and tells the user whether it filled.
* ctrader-mcp-servers: a Remote `get_spot_prices` row can come with prices and no `error` while its market is closed, carrying the `timestamp` of its last quote, so the agent gives each quote with the time of its `timestamp`, calls a quote whose time lies well before the current time or the newest quote of the read the market's last quote and not a current price, presents the spread of such a row as that of the last quote and not as a cost of trading now, and takes the current time from the environment or the user, since no answer carries the time of the read.
* ctrader-mcp-servers and ctrader-cli: the `volume` of a Remote or a Local trend bar and of a bar of the CLI `candles` is the number of ticks of its period, so the agent gives it as read and never divides it by 100 or turns it into units or lots; the Remote conversion of `volume` into units and lots covers orders, positions, deals and Advanced Take Profit levels.
* ctrader-mcp-servers and ctrader-cli: after a market order sent against an open position of the same symbol on the other side, on an account that does not hedge, the agent sets no stop loss or take profit at once, reports what the read shows and, when a position of the symbol remains, asks the user which levels it is to carry; the Local recipe and the CLI read the account's `accountType` before such an order, and a pending order that rests still gets a missing level at once.

## 0.2.3 (2026-11-27)


### Changes

* ctrader-mcp-servers: when the user gives the levels of a Remote MARKET or MARKET_RANGE order as prices, the agent counts the relative distances from the quote of `get_spot_prices` read before the call is shown, the ask for a buy and the bid for a sell, shows each level in the confirmation as the user's price with the `relativeStopLoss` or `relativeTakeProfit` that is sent, says that the levels stand at those distances from the fill and can differ from the user's prices, and sends the confirmed distances without computing them again; a level missing after the fill is set to the user's price, or else to the price the confirmed distance gives from `entryPrice`, and a level at the confirmed distance is not treated as missing.
* ctrader-mcp-servers: a conversion from a symbol's quote currency to the account currency takes in `--quotes` the quote of a symbol that links the two currencies, found on the Remote server among the `get_symbols` rows by `baseAssetId` and `quoteAssetId` and on the Local server with `get_symbols` and `filter`, keyed by the names of its base and quote currency; when `conversion_rate.py` exits with code 4, the agent says that the conversion cannot be given and presents the figure in the quote currency, and sizes an order only from a rate the user gives; a figure whose quote currency is the account currency is already in the account currency, so the agent converts nothing and does not run `conversion_rate.py`.
* ctrader-mcp-servers: the agent sends the stop loss and take profit of a Remote LIMIT, STOP or STOP_LIMIT order as prices, on `create_order` and on `amend_order`, computed from the order's `limitPrice` or `stopPrice` when the user gives distances, since a resting order placed with the relative distances can read back without them; such an order that rests is read back with `get_pending_orders`, also after a lookup by `clientOrderId`, its `stopLoss` and `takeProfit` compared with the prices sent, and a confirmed protection it lacks is set with `amend_order`, which resends the order's price field, every protection that stays and its expiration; before an amend of an order whose row shows no stop loss and no take profit, the agent asks the user which ones the order keeps, since an amend that omits a leg removes it, while a level the user confirmed for an order just placed is set at once; on the Local server a limit or stop order is read back the same way and a missing protection is set with `amend_order` as a pip distance from its `targetPrice`.
* ctrader-mcp-servers: on the Remote server a symbol's pip size is 10 to the power of minus its `pipPosition`, the `--pip-size` the scripts take; the agent asks the user for the pip size, or works with a price distance, only when the symbol's `get_symbols` row cannot be read.
* ctrader-mcp-servers: since no Local tool serves a symbol's quote currency, the agent reads it from a symbol name made of two currency codes as `conversion_rate.py` reads a name, the last three of its six letters, and asks the user for every other symbol before sizing an order or converting a cost; the rate is 1 when that currency is the account currency, `depositAsset` of `get_balance`, and otherwise comes from `conversion_rate.py compute-chain` with a linking quote read with `get_spot_prices`.
* ctrader-mcp-servers: the agent never calls the Local `get_account_statistics` figures lifetime results, since no answer states their period or what `totalTrades` counts, and when `totalTrades` differs from the number of `get_order_history` items it presents them as the account statistics the app reports, not as figures of the loaded history.
* ctrader-cli: before `run` the agent agrees with the user how long the cBot is to work and how it ends, and names it in the confirmation: until the user asks to stop it, started without `timeout` and stopped with `stop --instance=<id>`; for a time the user names, under a `timeout` of that length; or until the cBot stops itself, with `--exit-on-stop`; `run` no longer takes the 240-second limit of `build` and `backtest`, which would end the cBot's run, and after the process ends the agent reads `cbots` and `positions`; exit 124 of a `run` under the time the user named is the agreed end of the run, so the agent reports the instances `cbots` lists and the positions still open and does not start `run` again.
* ctrader-cli: before any `stop`, cleanup included, the agent tells the user that the positions the cBot opened stay open, since the cTrader Help Centre says that stopping a cBot instance does not automatically close them, and after the `stop` it reads `positions` and reports the positions still open.
* ctrader-cli: the agent reads an `optimize` result from the completion summary, with the number of passes, the elapsed time and the best pass, and from the `.optres` file of `--optres`, which lists every pass, with an HTML report per pass in `--passes-dir`; it agrees the time limit of an optimization with the user before the run, and reads exit 124 without the summary as a run the limit ended, whose longer limit it agrees with the user before running it again.
* ctrader-mcp-servers: before a Local `startPlugin` the agent tells the user that the Local tools do not show which account the cBot trades on and that the cBot runs until it is stopped or, as a local instance, until the app closes, as the cTrader Help Centre says; before `stopPlugin` it says that stopping the cBot does not close the positions it opened, and after it reads `get_positions` and reports the positions still open.
* ctrader-mcp-servers: the Local `getIndicatorValues` answers the last `count` values of an output oldest first, the last one for the bar still forming, with no times; before reading an indicator just added the agent reads `listChartIndicators`, and when it lists `isRunning` `false` reads it once more a second later, then tells the user that the indicator has not started yet and reports no values when it still lists `false`; an empty `values` answer of a running indicator is read once more a second later and then reported as no values returned; since no Local tool names the line behind an `outputIndex`, the agent tells the user so when asked for one line of an indicator with several outputs and presents no index as a named line.
* ctrader-mcp-servers: the Local `open_chart` answers `timeframe` `null` when the call sends none, so the agent reads the new chart's timeframe from `list_charts` or `get_active_chart`.
* ctrader-mcp-servers: a Local `get_trendbars` bar carries `timestamp`, the time it opens, and a `d1` bar opens at the start of the symbol's trading day, which can fall on the evening before in UTC; the agent takes the day boundary from the `timestamp` of the `d1` bars, names a daily bar by the trading day it opens, a weekly and a monthly bar by the week and the month that start after its stamp, and sends `from` at or before the bar's `timestamp`, since a `from` later than the `timestamp` leaves the bar out; a session start of `get_symbol_sessions` can lie seconds after that `timestamp`, so the agent does not send it as the `from` of a daily bar.

## 0.2.2 (2026-11-26)


### Changes

* ctrader-cli: the skill no longer pre-approves `printenv`, so reading an environment variable asks the user like any other shell command.
* ctrader-cli: the agent starts `run` so that the shell stays free, reads `cbots` from a second call while the run is going as the read-back of `run`, reports the instances it lists, and takes the id for `stop --instance=<id>` from that list; after `stop` it reads `cbots` again.
* ctrader-mcp-servers: on a Remote data profile the agent changes a position's stop loss or take profit through `close_position_link` and a pending order through `cancel_order_link`, with the id read from `get_positions` or `get_pending_orders`, says which change to make, and reports the link as one that changes nothing until the trader acts in cTrader.
* ctrader-mcp-servers: on a Remote data profile the flatten recipe reads `get_positions` before it builds the cancel and close links, the cancel links first.
* ctrader-mcp-servers: for a MARKET_RANGE order the agent takes `baseSlippagePrice` from the quote read just before the call, the ask for a buy and the bid for a sell, unless the user names the base price, counts `slippageInPoints` from it, and names the base price and the bound in the confirmation.
* ctrader-mcp-servers: for a market link whose slippage bound the user gave as a price distance while the pip size is not known, the agent asks for the range in pips or for the pip size, and builds the link without a bound only when the user agrees, saying that it carries none.
* ctrader-mcp-servers: the agent calls `get_symbols` with `names` or `symbolIds` and `get_assets` with `assetIds` or `names`, as their descriptions ask; since either answer can hold every symbol or asset, the agent takes the rows of the task by id or name, never by their position, reads no number of matches from the number of rows, and keeps the rows for the session.
* ctrader-mcp-servers: on the Remote server the agent takes a symbol's quote and base currency from `get_assets`, the `name` of the row whose `assetId` equals the symbol's `quoteAssetId` or `baseAssetId`, and converts a spread cost, a floating profit and the rate a size needs from that quote currency to the account currency with `conversion_rate.py compute-chain`.
* ctrader-mcp-servers: the agent checks a new order's stop loss against its entry and a new stop loss of an open position against the current quote: a long position's below the bid, a short position's above the ask.
* ctrader-mcp-servers: `trading-math.md` names the data and trading files of each server as the layer files that hold the server's inputs, and the file table of the skill sends pips, sizing, margin, conversion, profit and swap work to them beside `trading-math.md`.
* ctrader-mcp-servers: in the Remote error table, 404 `ORDER_NOT_FOUND` from `get_order_by_client_order_id` means that no order carries the id, and a `create_order` that timed out or answered `UPSTREAM_ERROR` or `UPSTREAM_UNAVAILABLE` is looked up by its `clientOrderId` and resent with the same id on that 404, as `remote-trading.md` says.
* ctrader-mcp-servers: a Remote `create_order` answered 429 is resent unchanged, with the same `clientOrderId`, after the wait `Retry-After` gives.
* ctrader-mcp-servers: the pip distances of a Local pending order count from its `targetPrice`, the stop price of a stop-limit order, or from the new entry price when the same `amend_order` sends `entryPrice`; the agent turns a price the user gives into pips from that reference with `pip_math.py price-to-pips`, after checking that the level lies on its leg's side, and compares the price read back with the user's price.
* ctrader-mcp-servers: `amend_order` on the Local server does not change a stop-limit order and answers `Modify error: slippageInPoints have to be defined`; before any call the agent tells the user and offers to cancel the order and place a new one, each call confirmed, or to change it in cTrader, and says that a new order placed through the Local server has its limit at the stop price again. The new order takes the values the user changes and the rest from the read of the old one, its trigger method from the request kept in the conversation or from the user, and a label of its own.
* ctrader-mcp-servers: a stop-limit order placed through the Local server has its limit at the stop price, a limit range of 0, whatever `limitPrice` the call sends, so the agent sends `limitPrice` equal to `stopPrice` and asks the user for no limit price. Before the confirmation the agent tells the user so and offers to place the order that way, in cTrader where the limit range can be set, or through a Remote trading profile with `slippageInPoints`; a request whose limit differs from its stop price waits for the user's choice among these ways, also when the user's message confirmed its steps in advance. The confirmation names the limit at the stop price and, for an order with a stop loss or take profit, says that a level which does not apply cannot be set through the Local server afterwards; in the recipe for opening a position, such a level of a stop-limit order goes back to the user. The agent never reports the requested `limitPrice` as the order's limit.
* ctrader-mcp-servers: a message that confirms the steps of order-changing calls in advance covers those steps as the user stated them, and the agent asks about a call that differs from them before sending it.
* ctrader-mcp-servers: before `update_indicator_parameters` on the Local server the agent asks the user for the parameter names as the indicator settings in cTrader show them, since no tool lists them, and sends each name exactly as shown, letter case included, one parameter per call, since a call with a known and an unknown name answers `updated`; when a name is refused as an unknown parameter, the agent shows the user the text and asks again, and when a setting chosen from a list refuses the name of a choice, it takes the number of the choice from the user or tells the user to change the setting in cTrader. It says that no tool reads the change back.
* ctrader-mcp-servers: when the user gives the levels of a Local market order as prices, the agent turns them into pips from the quote read before the call is shown, the ask for a buy and the bid for a sell, shows each level in the confirmation as the user's price with the distance that is sent, says that the levels stand at those distances from the fill and can differ from the user's prices, and sends the confirmed distances without computing them again; a level that reads back `null` is set to the user's price, a level at the confirmed distance is not treated as missing, and moving it to the exact price is an `amend_position` the user confirms.
* ctrader-mcp-servers: the agent reads `side` of a Local `get_deals` item as the position's side, not the side of the closing execution, also in the flatten recipe.
* ctrader-mcp-servers: to draw a trade's risk and reward on the Local server, the agent asks the user for the level to draw when the trade's stop loss or take profit is not set, saying that it sets nothing on the trade, sends `side` from the trade on every call, since a call without it draws a buy, and starts the drawing at the position's `openTime` or, for a pending order, at `utcTime` of `get_server_time` unless the user names another start.
* ctrader-mcp-servers: the agent does not present `high`, `low` and `open` of the Local `get_spot_prices` as a day's range or open, since the answer names no period, and takes a range from `get_trendbars`; for a range that reaches the present it adds bars of a shorter timeframe and the current quote, since the bar still forming is not returned.
* ctrader-mcp-servers: `apply_chart_template` on the Local server is among the calls that delete or overwrite: the agent reads the active chart and its indicators first and confirms, since the call replaces the chart's indicators with those saved in the template, and passes the template's name as `templateId`.

## 0.2.0 (2026-11-25)


### Features

* ctrader-mcp-servers: the skill opens with how to tell the Remote and the Local server apart by the tools only one of them serves, a side-by-side table of the units each server uses (symbols, volume, quote and order prices, protections, money, timestamps, demo or live), and the checks before and after every order-changing call: read whether the account is demo or live, confirm the exact call with the user, check the quote, the side, the protections, the price digits and the volume, then read the result back.
* ctrader-mcp-servers: six references, one per server and kind of task plus one shared: `references/remote-data.md`, `references/remote-trading.md`, `references/local-data.md`, `references/local-trading.md`, `references/local-app.md` and `references/trading-math.md`.
* ctrader-mcp-servers: recipes for a book snapshot, history and bars over a long window, a pre-trade snapshot, a cost comparison by spread, opening a position, changing protections, closing all or part of a position or flattening the book, sizing a position from risk and, on the Local server, drawing a trade's risk and reward on a chart.
* ctrader-mcp-servers: `units_encoding.py quote-to-price` turns Remote quote integers into display prices, dividing by 100000 for every symbol; `units_encoding.py check-volume` reports whether a size lies on the Local volume grid and within its limits, with the nearest valid sizes below and above, and changes nothing.
* ctrader-mcp-servers: `pip_math.py distance` gives a distance as `relative` (1/100000 of the price, the unit of `relativeStopLoss` and `relativeTakeProfit`) and as `points` (1/10^digits, the unit of `slippageInPoints`), and refuses with exit code 2 a relative distance that is not a multiple of 10^(5 - digits), naming the two nearest valid ones.
* ctrader-cli: the bundled script `scripts/extract_result.py` finds the result in the captured standard output of a CLI command by a key only the result carries (`--key`), prints the period tokens (`--periods`) or a message line (`--message`), and checks itself with `--self-test`. The written rule it implements works without Python.
* ctrader-cli: the skill covers each install route: winget and the copy bundled with the cTrader desktop application on Windows, the Homebrew tap on macOS and Linux, and the container image on any OS with Docker. Where builds differ, the agent follows the build's own `--help`.
* ctrader-cli: `optimize`, the backtest options for cached data, real conversion rates, the equity chart axis, Monte Carlo simulation and `--exit-on-stop`, and `--reconnect-timeout` of `run`, each where the build's `--help` lists it.
* ctrader-cli: `create` scaffolds plugins as well as cBots and indicators, with the kind given as `--kind=`.

### Changes

* ctrader-mcp-servers: digits, pip size and lot size come from the connected server: `get_symbol_details` on the Local server, and on the Remote server `get_symbols` for digits and the lot size by instrument class, with a test order of the smallest volume offered, after the user confirms it, when the class does not settle the lot size.
* ctrader-mcp-servers: a stop loss or take profit the user confirmed that is missing after the call is set at once to exactly that value and reported, and the confirmation before the order says so.
* ctrader-mcp-servers: before a close or a cancel the agent names the position by symbol, side and entry price, or the order by symbol, side and price, in the message that shows the call.
* ctrader-mcp-servers: on the Remote server a new order gets a `clientOrderId` that no earlier order carries, looked up with `get_order_by_client_order_id` before the call is shown.
* ctrader-mcp-servers: on the Local server the agent starts a cBot only when the user asks for that start. Before `startPlugin` it shows the cBot, says whether the account is demo or live and gets a yes; after it, it reads the cBot's state back.
* ctrader-mcp-servers: on the Remote server, a call answered with 429 is sent again after the wait `Retry-After` gives, in place of fixed rate figures.
* ctrader-mcp-servers: examples carry placeholders such as `<position-id>` and `<order-id>` in place of identifiers.
* ctrader-mcp-servers: `units_encoding.py lots-to-units` and `lots-to-cents` print the exact product instead of rounding it down, and `units-to-lots` takes decimal units.
* ctrader-mcp-servers: `pip_math.py pips-to-price` takes decimal pips and prints `rounded`, with `unrounded_price` when rounding to `--digits` moved the level; `pip_math.py price-to-pips` prints the exact `pip_distance`, decimals included, and its `--digits` is optional.
* ctrader-mcp-servers: `position_sizing.py` sizes from the stop distance, given as `--sl-pips` with `--pip-size` or as `--price-distance`, and `--conversion-rate` and `--lot-size` are required, a call without either is refused with exit code 2 (a missing conversion rate was taken as 1), and the lot size only expresses the size in lots. It prints exact `units` and `lots`, `cents` (the Remote volume, rounded down so the risk stays at or below the target) with `cents_rounded_down`, and `risk_currency_amount`. `--min-volume`, `--max-volume` and `--volume-step`, given together in units, add `on_grid`, `within_limits`, `below` and `above`; nothing is rounded to the step or clipped to the limits.
* ctrader-mcp-servers: `conversion_rate.py` refuses a missing chain with exit code 4 and prints no `rate`, where it printed a rate of 0 with exit code 0.
* ctrader-mcp-servers: `tiered_margin.py` takes a decimal `--volume-base-units`, and refuses with exit code 2 an account currency other than USD given without `--account-currency-rate-vs-usd`, where it printed the USD figure as the margin in the account currency, and a USD account given an `--account-currency-rate-vs-usd` other than 1, where it printed the figure scaled by that rate as the margin in USD.
* ctrader-mcp-servers: every script keeps `--self-test`, with its cases matched to the behavior above.
* ctrader-cli: the result of a command is found by its content, never by its position, because standard output can carry log lines, a line that repeats the command and the result printed twice.
* ctrader-cli: `run` and `stop` join the commands that change state. The agent starts `run` only when the user asks for that run, and stops without asking again only an instance it started for the user.
* ctrader-cli: before and after every state-changing command the agent checks each option against `--help`, passes `--account`, reads the entity back and compares it with what it expected; a stop loss or take profit the user authorized that did not apply is set at once to the authorized value.
* ctrader-cli: before each state-changing command the agent tells the user what it does, and for a cancel or a close names the order by symbol, side and price, or the position by symbol, side and entry price.
* ctrader-cli: examples carry placeholders such as `<account>`, `<order-id>` and `<position-id>` in place of numbers.
* The bundled scripts of both skills need Python 3.11 or newer and run as `python3` on macOS and Linux and as `python` on Windows, or `py` where `python` is not on the path. The README states the same.
* Each skill pre-approves a Python command only when the command names one of the skill's own bundled scripts, under `python3`, `python` and `py`; a Python command that names none of them asks the user. The ctrader-mcp-servers skill pre-approved every `python` command before.
* `install.sh`: wrong arguments, such as an unknown option or a second directory, end it with a non-zero exit status and the usage text on standard error, before anything is installed.
* `install.sh`: `--force` replaces only the skill folders of this package and leaves the other skills and files of the install folder as they are.
